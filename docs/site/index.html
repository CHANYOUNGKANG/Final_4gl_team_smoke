설계를 설명하는 화면입니다. 실제 측정값은 프로젝트 시연 기록표에 남깁니다. 단계별 시나리오는 배포 시뮬레이터에서 볼 수 있습니다.

네 가지 일을 한 흐름으로 맡습니다

망을 나누는 일, 서버를 정비하는 일, 클라우드로 옮기는 일, 배포를 자동화하는 일은 서로의 결과를 넘겨받아야 끝납니다. 그래서 한 팀이 처음부터 끝까지 맡고, 각 단계의 확인 결과를 다음 단계의 시작 조건으로 씁니다.

바꾸는 것
코드를 올리면 Jenkins가 테스트·이미지 빌드를 하고, 새 버전을 옆에 띄워 검사한 뒤에만 트래픽을 넘깁니다. 넘긴 뒤 이상이 보이면 이전 버전으로 되돌립니다.
판단 기준
커밋·빌드·이미지 태그가 한 줄로 이어지고, 배포 중 조회 실패 0건, 롤백 후 이전 버전 응답.

해든정밀㈜ 공지·자료실 이전

정밀 가공 부품을 만드는 해든정밀은 고객사와 협력사에 납품 일정, 품질 인증서, 도면과 카탈로그를 공지·자료실로 배포합니다. 기존 글과 파일을 하나도 잃지 않고, 배포 중에도 조회가 끊기지 않을 것. 이것이 의뢰 조건이었습니다.

의뢰 당시

  • 본사 서버 한 대가 사내 업무와 대외 공지·자료실을 함께 처리
  • 웹 서버에서 비정상 접근 흔적이 발견됐지만 망이 나뉘지 않아 경로 추적이 어려움
  • 첨부파일 증가로 디스크 부족
  • 배포할 때마다 Tomcat 재시작으로 공지 조회 중단

이전 후 목표 구조

  • 본사는 관리·서비스·서버팜 VLAN으로 분리, 지사는 VPN으로 서비스망에만 접근
  • 공지·자료실은 두 가용 영역의 EKS, 게시글은 RDS, 첨부는 S3
  • 첨부마다 SHA-256을 기록해 이관 전후와 다운로드 시점에 대조
  • Blue·Green 두 버전을 두고 검사를 통과한 버전으로만 전환, 실패 시 자동 복귀
