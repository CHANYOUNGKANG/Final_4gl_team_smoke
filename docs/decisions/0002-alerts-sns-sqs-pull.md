# ADR-0002: 운영 알림은 SNS → SQS에 쌓고 본사 메일 서버가 가져간다

- **상태**: 제안
- **날짜**: 2026-11-25
- **담당**: 이준호 · 이우빈

## 상황

CloudWatch 알람과 Jenkins 배포 결과를 본사 메일 서버(`10.0.30.10`)의 운영 메일함으로 받아야 한다. 메일 서버는 GNS3 NAT 뒤에 있어 밖에서 들어오는 SMTP(25)를 받기 어렵고, 학원 망에서는 공인 IP·25번 포트를 열기 어렵다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| SNS 이메일 구독 → MX → 메일 서버 | 표준 방식 | MX 레코드·공인 IP·ASA 25번 고정 NAT 필요, 공격 면 증가 |
| **SNS → SQS ← 메일 서버가 HTTPS로 가져감** | 나가는 443만 필요, 메일 서버가 꺼져도 큐에 남음 | 가져오는 스크립트(cron)를 운영해야 함 |

## 결정

SNS 주제 하나에 CloudWatch·Jenkins를 모으고 SQS 큐를 구독시킨다. 메일 서버의 `sqs2mail.sh`가 1분마다 큐를 읽어 메일로 바꾸고 보낸 것만 지운다.

## 결과

- 좋아지는 것: 본사로 들어오는 포트를 열지 않는다. 알림 유실이 줄어든다.
- 감수하는 것: 최대 1분 지연, IAM 권한(Receive·DeleteMessage)을 그 큐로만 제한해야 한다.
- 확인 방법: `set-alarm-state`로 알람을 울려 1분 안에 ops@ 수신, 결과 기록표 “접근 통제·운영 알림”.
