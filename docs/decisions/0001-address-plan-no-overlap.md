# ADR-0001: 본사·지사·AWS 대역을 겹치지 않게 나누고 한 파일로 관리한다

- **상태**: 제안
- **날짜**: 2026-11-25
- **담당**: 강민서 · 이우빈 (정리: 강찬영)

## 상황

본사 GNS3, 지사, AWS VPC가 VPN·인터넷 경유로 서로 통신한다. AWS 콘솔 기본 VPC 대역(`10.0.0.0/16`)을 그대로 쓰면 본사 대역과 겹쳐 이관·알림 경로의 라우팅이 모호해진다. 또 주소가 대시보드·문서·구성도에 흩어지면 하나만 고쳐 서로 달라진다.

## 검토한 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 기본값 사용 (`10.0.0.0/16` 공유) | 설정이 쉬움 | 본사와 겹침 → 경로 충돌 |
| 구역별 분리 + 문서마다 직접 기재 | 이해하기 쉬움 | 문서끼리 어긋남 |
| **구역별 분리 + `topology.json` 단일 기준** | 겹침을 자동 검사, 구성도·표 자동 생성 | 값 변경도 PR로 해야 함 |

## 결정

본사 `10.0.0.0/16`, 지사 `10.1.0.0/16`, AWS `10.100.0.0/16`, GNS3 공인 역할은 문서용 대역 `198.51.100.0/24`·`203.0.113.0/24`를 쓴다. 값은 [topology.json](../architecture/topology.json)에만 적고, 구성도와 [IP 대역표](../architecture/ip-plan.md)는 Actions가 만든다.

## 결과

- 좋아지는 것: 겹침·잘못된 CIDR은 PR 검사에서 실패한다. 구성도와 문서가 항상 같다.
- 감수하는 것: GNS3 대시보드는 사람이 같은 값으로 맞춰야 한다.
- 확인 방법: PR의 “문서 · 구성도 검사”, 첫날 확인 순서([ip-plan.md](../architecture/ip-plan.md#확인-순서-구축-첫날)).
