## 기술적 특징 (슬라이드 한 줄씩)

- **검증된 스크립트는 건드리지 않는다** — 백업 메일은 원래 스크립트를 감싸는 래퍼로 추가. 복구 시험을 통과한 백업 로직은 그대로 유지
- **"옮겼다"를 숫자로 증명** — 건수 + 본문·첨부 목록 SHA-256 기준값을 미리 만들어, 백업 복구와 AWS 이관 모두 같은 조회로 대조
- **최소 권한** — 앱 DB 계정은 읽기·쓰기만, 메일 발송은 사내 대역만, node_exporter 는 관리 대역만, Tomcat 은 서버 안에서만
- **기록은 다른 서버에** — 로그와 백업 사본을 mgmt 에 따로 두어 서버 하나가 망가져도 추적·복구 가능
- **VPN 없이도 연결되는 알림 설계** — AWS 알림은 SNS → SQS 에 쌓고 mgmt 가 HTTPS 로 꺼내 오는 방식 (구현은 AWS 값 수령 후)

## 발표에서 숨기지 않을 한계

- 백업이 하루 1회라 마지막 백업 이후 데이터는 잃을 수 있다 (RPO 최대 24시간)
- 온프레미스 3대는 네트워크 장비 경로가 아닌 VMware NAT 임시 경로로 연결해 시험했다
- AWS 쪽 알림(배포·CloudWatch)은 설계와 요청까지 했고 수신은 아직이다
